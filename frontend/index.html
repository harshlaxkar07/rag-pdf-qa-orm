The ingestion pipeline

  1. Load — every page of the PDF is read into a document object with its page number kept as metadata.
  2. Split — text is chunked at 1000 characters with a 200-character overlap so sentences are never cut in half.
  3. Embed — each chunk becomes a 384-dimension vector from all-MiniLM-L6-v2.
  4. Store — vectors and metadata land in PostgreSQL through the SQLAlchemy ORM with a pgvector column, indexed for cosine similarity.

How this build works

This build models the vector store as a declarative SQLAlchemy entity. Chunks are ordinary mapped objects with a pgvector column, so similarity search is expressed as a normal ORM query and every row is a typed Python object.
